# #458 퀘스트 물건 버림·툴팁 정합성 — 2026-09-27

#457 실제 봉인물 검수에서 발견한 두 UI 오류를 고쳤다. can_discard=false인 봉인패·고리·사슬을 커서에 든 채 창 밖을 누르면 버려졌고, 툴팁에는 버리기 안내와 판매 불가 물건의 판매가1엽전이 있었다. 변경 전 실제 입력 검수70개가 이 결함을 재현한다. before 모드는 결함 발생 후 검수 표본만 복구하며 게임 규칙을 바꾸지 않는다.

명시적인 창 밖 좌클릭 버림만 can_discard로 거부한다. 「퀘스트 물건은 버릴 수 없다」를 보여 주고 같은 물건을 커서에 유지하므로 실제 클릭으로 다시 가방에 놓을 수 있다. HUD 벨트 전달 경로는 기존대로 먼저 처리한다. 퀘스트 가방 툴팁은 「좌클릭: 들기」·「퀘스트 물건 · 팔기·버리기 불가」를 보여 주며, 좌판이 열려도 판매가나 판매·버리기 동작을 안내하지 않는다. 아이템 정의의 price1을 변경하거나 새 판매 규칙을 만들지 않았다.

왜 이 구조인가: 명시적인 버림 입력에서만 can_discard를 확인하면 기존 판매/퀘스트 계약을 지키면서 닫기 때의 회수 안전망을 유지한다. _drop_held 전체를 금지하는 대안은 꽉 찬 가방의 자동 배치 실패에도 관여해 물건 소실이나 남은 커서를 만들 수 있으므로 기각했다. 툴팁도 같은 can_discard를 읽어 조작과 설명이 일치한다.

실제 입력 회귀: 봉인3 각각 창 밖 버림 거부·커서 원본 유지·바닥 생성 없음·거부 문구·원자리 되놓기, 플레이어 이동/엽전 변경 없음. 기존 Ctrl 버림/우클릭 판매 거부, 실제 김 영감 대화/거래 선택, 각 Alt 이름표 클릭으로 봉인3 회수도 통과했다. 일반 탕약3은 실제 창 밖 클릭으로 버려지고 수량3을 유지한다. 봉인패를 든 뒤 남은 칸을 최대 스택 탕약으로 채워 창을 닫으면 같은 퀘스트 물건을 발밑에 보존한다. 한 칸을 비운 뒤 실제 Alt 이름표 호버/클릭으로 걸어가 회수해 같은 물건·쌓기1이 돌아온다. item_system_v2 §14.5의 이 예외는 의도적인 버리기와 구별한다.
