# #266 후보 검수 기록

2026-10-04 · 구현 계약 = `gamble_266.md`. 게임 main 미착륙.

게임 main 미착륙·외형 임시 대역·PD 확인 및 다른 계열 교차 검수 대기.

- 기능: 흑랑 처치 후 장터/반닫이 인근 등장, 첫 만남 저장, 8부위 견적·미식별 매직 이상 구매, 구매 자동 저장.
- 구조: Gamble은 ItemGen을 재사용하고 GambleService가 읽기 모델·revision·최신 거리/커서/돈 검사와 거래 확정을 맡는다. 덤 쪽3%까지 함께 들어갈 때만 돈·물건·RNG를 확정한다. UI에서 먼저 돈을 빼거나 난수를 굴리는 구조는 거절 때의 상태 복구 부담 때문에 기각했다.
- 표현: merchant_v2 임시 대역, 억쇠 초상/새 음성 없음. 도호 그림은 기존 대화 띠의 듣는 인물이며 억쇠의 초상으로 등록하지 않았다. 억쇠 원화 후보는 #625, 전용 창은 #273.
- 실제검사: Unit 92개 스크립트·도구 검사 PASS, 전체 E2E132/132(shared122+solo10), 창 모드 gamble23/stash50/vendor54, 사진 대기만 보완한 뒤 gamble26개 PASS·러너 자기검사5/5.
- 사전: 실제136항목·83아이콘 JSON/HTML 생성 PASS. 보따리·유니크/세트 등급 전체 확률·쪽 덤 출처 반영. 공식 공유 사전은 #619 선행 착륙 뒤에 갱신한다.
- 원본로그: logs/에 stdout/stderr 바이트 그대로, raw_byte_manifest.json에 SHA. 초기 파싱 실패와 종료 누수 수정 전 기록도 삭제하지 않았다. 최종 Godot 단위/사전의 기존 allowlist 종료 경고3 ObjectDB/2 resources는 남아 있어 무경고라고 주장하지 않는다.
- 다른 계열 검수: Cursor 지정 CLI 없음, Grok CLI 인증 없음. Codex 자체 검수는 다른 계열 검수로 세지 않았다.

사진5장 각300KB 이하·1280폭. 장터 변경 전후 같은 구도, 기존 before 사진을 보존. 구매/복원 사진은 타이핑 완료를 기다린 두 번째 실제 실행 결과다. 최초14장도 screenshots/initial_14/에 별도 보존한다. 압축과 배치 외 그림 수정은 없다.

왜 이 구조인가: 기존 ItemGen·가방 크기·저장 규칙·NPC 대본을 그대로 쓰면 #273 UI를 연결할 때 경제 규칙을 다시 만들지 않는다. 새 원화/3D 생성은 기능 거래와 독립시키고, 임시 배우의 시각 판정은 PD에게 남긴다.
