# #744 캐릭터 자료관 제작·검수

조회 정본: `C:/workspace/joseon-assets/catalog/characters/index.html`. 데이터 정본은 같은 폴더 `catalog.json`이며 승인 원화/부분 승인/추천/기각과 현재 연결/실제 로드/월드 표시/최신성을 별도로 유지한다. 도호, 마을 NPC, 주모/구미호를 중심으로 8인물·9형태·49자료를 수록했다.

## 검증

- `catalogue-validation.json`: 경로·SHA·스키마·자료 근거 검사 ok=true. 모델7 current, 월드6 indeterminate.
- `stale-detection-verification.json`: 격리 사본에서 jumo 설정만 바꿨을 때 해당 렌더만 stale. 승인 정보 SHA 동일. 실제 게임 파일은 수정하지 않았다.
- 도구 단위15, 조회 생성기 단위7, UI 회귀 검사 통과. 실제 브라우저에서 검색·선택·버전·모델/게임 사진·확대·320px 줄바꿈을 확인했다. 캡처 없는 매체는 다른 매체의 로드/최신성 성공을 물려받지 않는다.
- 게임 전체 단위/도구 층은 PASS. 전체 e2e 첫 실행은 footsteps 최소 간격 검사 하나가 0.137초로 FAIL했고, 게임 코드 변경 없이 footsteps 단독 재검사는 PASS. 첫 전체 실행을 통과로 바꾸어 기록하지 않는다. phase별 전체 결과와 원시 바이트 로그는 `verification.json` 및 `logs/`에 보존했다.

## 적용 범위와 운영

구미호 본체의 현재 보스 연결은 흑랑 대체 GLB다. #741 v2 톤 승인과 #742 H01 추천은 전면 외형 승인이나 게임 반입으로 확대하지 않았다. 중립 모델 뷰어와 실제 마을 사진은 촬영 조건이 다르며, 동적 월드 사진의 의존성이 미완전하여 최신성 판정 불가로 표시한다. 기존 종료 자원 경고도 raw 로그에 보존했다.

원본은 SHA 경로 또는 기존 정본 경로+SHA+커밋으로 보존하고 파생 미리보기의 crop/derived_from를 기록한다. JSON 한 곳에서 조회 화면을 생성하는 이유는 이미지와 승인 이력을 중복 입력하다가 판정이 엇갈리는 문제를 줄이기 위해서다. 문서/스프레드시트에 별도로 승인 상태를 적는 대안은 동기화 책임이 늘어나므로 채택하지 않았다.

후속 원화·반입·설정 변경 카드마다 게임 `docs/design/character_art_catalogue_ops.md`의 dry-run → 근거/정본 갱신 → check → 필요한 실제 캡처 → 조회 재생성 → 화면 검수를 수행한다. 승인·과거 원본은 보존한다. 신규 예약 자동화나 외부 공개는 만들지 않았다.
