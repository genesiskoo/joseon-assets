## 납품

- 이 폴더 루트의 게임 ID와 같은 이름 PNG 17개: **128×128, RGBA 투명**.
- 아트 긴 변 103px(80.47%), 비율 보존, 중앙 정렬. 투명 바깥 여백 최소 12px. 실제 알파 경계·패딩은 `manifest.json`.
- `contact_icons_h1.png`: 신작128px / 밝고 어두운 배경 / 32·40px 축소 / 구작 대조. 배경 타일·라벨은 검수 시트에만 있으며 납품 아이콘에는 없다.
- `sources/`: imagegen 원본 17장. `rejected/quilted_robe_v1.png`: 붉은 띠가 따라붙어 기각한 누비옷 초안.
- `source_map.json`: 재현용 ID·이름·프롬프트·원본 상대 경로. `generation_manifest.json`: 공통 참조와 생성/수정 이력.
- `package_icons.py`: 알파 경계 트림→비율 보존 축소→128 캔버스 패키징. 색/선/형태 수정과 배경 제거는 하지 않는다.

## 제작·검수

내장 imagegen 도구로 아이템별17회 생성 + 누비옷1회 수정. H1 승인 원본 왼쪽 캐릭터의 선·큰 무광 명암, H1 소품 시트의 재질을 참조했다. 기존 픽셀 그림의 실루엣·색 계열을 이어간다. 특정 모델 버전은 도구가 노출하지 않아 명시하지 않는다.

검4종(목검/철검/장검/환도), 의복3종(무명옷/누비옷/가죽갑), 신발2종, 장신구2종, 무명띠, 소비4종, 엽전1종. 무명옷=접힌 상아색 옷, 누비옷=남색 전신, 은가락지=초록 보석, 식별부=붉은 필획, 귀환부=큰 먹문양을 유지한다.

17개 정확한 ID·PNG 크기·알파·여백·해시 자동 검사 통과. 모든 원본과 전체 대조표를 직접 확인했다. 세로 장검은 32px 칸에서는 얇게 보이므로 다칸 장비 영역에서 원본 비율을 살려 배치한다. 어두운 가죽/남색 의복은 밝기 차이가 있는 슬롯 바탕에 놓고 아이콘 틴트는 흰색으로 유지한다.

왜 이 구조인가: 같은 H1 참조·광원·화풍 조건으로 각각 생성하고 실제 가시 경계를 기준으로 패키징하면 항목 간 스타일과 UI 안전영역을 맞출 수 있다. 한 장짜리 시트를 생성해 자르는 방식은 개별 형태·해상도 통제가 약해 사용하지 않았다.

## 반입 담당자 안내

루트 PNG17개만 게임용 폴더로 copy하고 `data/items/<id>.tres`의 `ItemDef.icon`을 각 ID 파일에 연결한다. 후보 원본·기각본·대조표는 런타임 자산 폴더에 넣지 않는다. 이미지 자체의 알파 여백을 고려해 가방/장비/벨트/상점에서 가시 크기를 검사한다. 별도 검수 환경에서 선형 필터와 현행 nearest를 비교한 뒤 필터를 선택한다. 이 납품에서 게임 GLB·UI 코드·아이템 데이터·기존 아이콘은 변경하지 않았다.

게임 반입 후 `test_items`와 `ui_windows` 및 실제 입력 영역 검수는 반입 카드에서 수행한다. 이 폴더의 검수는 독립 이미지 제작·규격 검수이며 실제 인게임 합격을 뜻하지 않는다.

재패키징(저장소 루트에서):

```powershell
python workbench/ui/icons_h1/package_icons.py workbench/ui/icons_h1/source_map.json --output workbench/ui/icons_h1 --complete --repo ../joseon
```

검수 시트의 글자는 Windows 시스템 폰트를 이용해 렌더했지만 폰트 파일은 납품물에 포함하지 않는다.
