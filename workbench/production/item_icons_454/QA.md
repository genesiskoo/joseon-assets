확대 원화/40px 파일 축소는 overview.jpg다. ui_before.jpg/ui_after.jpg는 같은 배치의 **실제 Godot 공통 UiSkin.item_slot/item_icon 렌더**로 현재 글리프/후보를 비교한다. 현재 가방과 같은 padding8이며 현재40px칸과 검정40px를 함께 보인다. ui_sizes.jpg는30/48/60px의 일반/검정칸이다. 40px에서 판·고리·사슬의 형태를 구별할 수 있다. 30px에서는 문양·마모·링크 이음의 세부가 상당히 사라지며 형태와 넓은 명암이 주 정보다. 원화의 장식이 작은 칸에서도 모두 읽힌다고 보장하지 않는다.

검증: 원본/후보3장의 알파·여백·점유·해시 PASS, 현재 정의67파일(ItemDef66+인덱스)와 채택 PNG35파일 SHA256 보존. main/WT의 정의는 LF/CRLF를 제외하면 같은 내용이다. UiSkin 검수판의 기존 패랭이·가죽신·무명띠 영역3곳은 전후 픽셀 동일하다. Godot before/after/sizes3모드 PASS, SCRIPT ERROR/ERROR0, 문서 예산 PASS. JPG4장 모두1280×720/각300KB이하, 합239371B. 로그 원본/명령/시각/해시는 reports/454/2026-09-27에 보존하고 인코딩은 verification.json에 기록했다.

이3종은 #274 핵심73 밖의 추가 퀘스트 물건이다. 채택 전후 모두 핵심잔여55가 유지된다. 현재 게임의 icon 공백3개도 이 단계에서는 그대로다. 후보는 검수 프로세스 메모리로만 올려 실제 게임 경로에 설치하지 않았다. 게임 코드·퀘스트 규칙·가격·드랍·모델·애니 변경 없음. 원화 채택 후 실제 가방/줍기/봉인 사용 반입 검수는 별도 카드다. 실행 코드가 같으므로 전체 플레이 회귀검사를 반복하지 않고 자산/공유 렌더/기존 파일 보존/문서 예산을 확인했다. 전체 플레이 회귀를 새로 돌렸다는 결과로 보아서는 안 된다.

왜 이 구조인가: 넓은 판·열린 고리·연결된 사슬을 별도 원화로 만들면 이미 있는 퀘스트 물건을 작은 가방 칸에서 구별할 수 있다. 효과 중심 추상 문양은 실물의 차이를 흐리고 UiSkin과 겹치므로 기각했다. 실제 공유 렌더와 파일 보존 검증으로 채택 전에 비교 가능한 결과를 남겼다. 사양은 docs/design/item_icons_454.md다.
