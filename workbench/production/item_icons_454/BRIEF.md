## 1. 규격과 범위

정본 `item_catalog_v2.md` §6.4 · `item_system_v2.md` §14.4·14.5·17. 현재 정의3종은 1×1칸, max_stack=1, quest_item=true, icon 없음이다. 흑랑의 봉인패(seal_heukrang), 장산범의 봉인고리(seal_jangsanbeom), 불가살이의 사슬 조각(seal_bulgasari)의 후보만 만든다. 가방 논리40px/2배80×80 RGBA, 채택 D1 실물 중심 채색·윗왼쪽 빛·절제한 재질·큰 명암을 유지한다. 원본은 그대로 보존하고 승인 alpha16/8%여백/Lanczos 패킹을 사용한다. 핵심73 밖의 추가 퀘스트 물건이므로 이3종이 채택되어도 #274 핵심잔여55는 같다.

## 3. 생산과 검수

내장 image_gen, 물건별 독립 투명 원화. 기존 가죽신·청심환은 화풍 참고2장이다. 원본/프롬프트/참조/생성경로/해시를 자산 생산 폴더에 저장한다. 실제 공통 UiSkin·궁서 제목을 쓰는 외부 Godot 검수판으로 현재 글리프/후보를 같은 구도에서 비교하고40px·검정슬롯·30/48/60px를 검수한다. 후보는 검수 프로세스 메모리로만 올려 실제 게임 아이콘을 설치하지 않는다. 현재 모든 ItemDef·채택 items/skills PNG의 SHA를 보존한다. JPG1280폭≤300KB,4장; 원본/전체로그는 joseon-assets reports/454에 둔다. 원화 채택 후 실제 가방/상점/드랍 검수와 반입은 후속 카드다.

## 4. 왜 이 구조인가

현재 정의의 마지막 아이콘 공백3개를 먼저 채우면 이미 구현된 퀘스트 물건을 가방에서 식별할 수 있다. 넓은 판·열린 고리·연결된 사슬을 독립 원화로 만들고 현재 점유 크기로 패킹해 작은 칸에서도 형태를 구별한다. 추상 문양이나 발광 효과는 실물의 차이를 흐리고 공통 UiSkin과 겹치므로 기각한다. 실제 공유 렌더와 기존 파일 해시를 함께 확인해 데이터 변경 없이 채택 가능한 후보로 보존한다.
